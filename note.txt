Developer A should be allowed to update ConfigMaps, but should NOT be allowed to delete Deployments or read Secrets.
That's the purpose of RBAC — Role-Based Access Control.
Instead of saying:
"Everyone can do everything."
you say:
"This identity can perform these specific actions on these specific resources."

2. What are we creating?
These four commands create four pieces of the permission system.

First: create an identity
kubectl create serviceaccount backend-team
This creates:
ServiceAccount: backend-team

Think of it as a Kubernetes identity.
For this exercise, we're pretending:

backend-team = the backend engineering team

Second: create the permission
kubectl create role configmap-editor \
  --verb=get,list,watch,update,patch \
  --resource=configmaps

This creates a Role called:
configmap-editor
It says:
Whoever gets this Role can work with ConfigMaps in this namespace using these actions.

The permissions mean:
get       → read one ConfigMap
list      → see ConfigMaps
watch     → watch for changes
update    → modify a ConfigMap
patch     → partially modify a ConfigMap

Notice something important:
There is no delete.
So this role cannot delete ConfigMaps.
That's the principle of least privilege.

3. Give the identity the permission
Now:
kubectl create rolebinding backend-team-can-edit-configmaps \
  --role=configmap-editor \
  --serviceaccount=default:backend-team

This connects the two:
backend-team
     │
     │ RoleBinding
     ▼
configmap-editor

So Kubernetes now knows:
backend-team is allowed to perform the actions defined in configmap-editor.

4. Test whether it actually works
This command:

kubectl auth can-i update configmaps \
  --as=system:serviceaccount:default:backend-team

is basically asking Kubernetes:
"If I were the backend-team ServiceAccount, would I be allowed to update a ConfigMap?"
You should get:

yes

Then:

kubectl auth can-i update configmaps \
  --as=system:serviceaccount:default:default

You should get:

no
because we didn't give the default ServiceAccount the configmap-editor Role.
